# Ortiz Go Templates

Welcome to **Ortiz Go Templates**, a collection of Go templates and example projects to help the community! 🚀

Each project is independent and ready to use or contribute to.

---

## Available Templates

| Template | Description | Repository |
|----------|------------|------------|
| CQRS API | Example using CQRS pattern in Go | [go-cqrs](https://github.com/ortiz-golang-templates/go-cqrs) |
| Event-Driven API | Example of event-driven architecture | [go-event-driven](https://github.com/ortiz-golang-templates/go-event-driven) |
| gRPC API | Example of Go API using gRPC | [go-grpc-api](https://github.com/ortiz-golang-templates/go-grpc-api) |
| GraphQL API | Example of Go API with GraphQL | [go-graphql](https://github.com/ortiz-golang-templates/go-graphql) |
| JSON-RPC API | Example of JSON-RPC API | [go-jsonrpc-api](https://github.com/ortiz-golang-templates/go-jsonrpc-api) |
| MongoDB API | Example using MongoDB | [go-mongodb](https://github.com/ortiz-golang-templates/go-mongodb) |
| MVC App | Go project following MVC structure | [go-mvc-app](https://github.com/ortiz-golang-templates/go-mvc-app) |
| NATS API | Example using NATS messaging | [go-nats-api](https://github.com/ortiz-golang-templates/go-nats-api) |
| RabbitMQ API | Example using RabbitMQ messaging | [go-rabbitmq-api](https://github.com/ortiz-golang-templates/go-rabbitmq-api) |
| REST API | Example of RESTful API | [go-rest-api](https://github.com/ortiz-golang-templates/go-rest-api) |
| Simple API | Minimal Go API template | [go-simple-api](https://github.com/ortiz-golang-templates/go-simple-api) |
| Simple MVC | Minimal MVC structure | [go-simple-mvc](https://github.com/ortiz-golang-templates/go-simple-mvc) |
| WebSocket App | Example using WebSockets | [go-websocket-app](https://github.com/ortiz-golang-templates/go-websocket-app) |

> Each repository is independent. You can clone, modify, open issues, or submit pull requests.

---

## How to Contribute

1. Pick the template you want to improve.  
2. Fork the corresponding repository.  
3. Create a branch for your changes.  
4. Submit a pull request for review.

---

## Contact

If you have questions or suggestions, open an **issue** in the corresponding repository or contact the Organization maintainers.
